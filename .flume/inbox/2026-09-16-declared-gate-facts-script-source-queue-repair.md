# Three rulings from a consumer pricing adoption before its next delivery (second consumer, a bay adopting after its next delivery, relayed by the operator)

- **A declared gate gets the engine's facts.** Their no-new-drift gates
  run a validator at the pre-entry trunk and at the gated commit; declared
  shell and script gates run with no context, so the gate would derive
  `HEAD^` — wrong for a multi-commit span, and a chain rediscovering a fact
  `GateContext` already holds. Ruled at `spec/harness.md`, the `gates`
  row: `FLUME_`-prefixed gate facts in the environment.
- **A declared script is a findings source.** Their plan prompt took a
  per-tick census as a prompt argument; slots are text. Ruled at *Declared
  findings sources*: a command the slice runs at the tip whose stdout is
  records, drained like the rest.
- **No queue state needs a hand edit.** They edited `pending.json` twice
  for fence repairs. Ruled at *The gates the discipline needs*: a refused
  queue is plan's to repair next tick; a refusal only a hand edit clears is
  the gate's defect. What derives: plan reads every refusal path against it.

Accepted as a design boundary, not filed: plan state the package re-derives
is only acceptable to a consumer whose state is re-derivable from the tree.
