# A declared script source re-emits a standing set every tick (consumer adoption answers)

`spec/harness.md` *Declared findings sources* rules a declared script as a
command the inbox slice runs at the tip, one JSON object per line, each
materialized as a record and drained like the rest. The consumer whose census
motivated the ruling measures a standing set, not per-tick events: 31
discrepancies today, stable within a few for a week. Drained means deleted,
so every tick that runs re-materializes the same 31 records and routes them
again.

Why it matters: the CI lane source in the same file already answers this
twice over — a stamp of the run and its failing titles, so a red that
persists unchanged wakes nothing, and a re-file rule where a title already
heading an entry or a question is not re-filed. A script's records get
neither.

The fork: the slice stamps a script's output as it stamps a lane's run and
re-files only what changed; or the script owes the delta, which puts the
stamp in every consumer's script.
