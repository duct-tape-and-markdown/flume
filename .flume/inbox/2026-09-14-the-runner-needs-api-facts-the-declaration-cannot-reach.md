# The declared runner needs engine facts the declaration cannot reach (interactive session)

Observed at 3447751. `declaration.runner` is a value the consumer constructs (`vitestRunner({ lanes })`), and the judge calls its `runAtBase`, which checks the base out detached and runs tests there. Two things that checkout needs live on `FlumeApi`, which a declaration never sees: the engine's lockfile-aware installer (`api.setupWorktree`) for the checkout's dependencies, and the state root's worktree base so a run that dies mid-flight leaves a directory the stale-worktree sweep reclaims. Loop 18 crashed on the first: no `prepare` was wired, the base had no `node_modules`, the runner threw.

Interim landed with this record: `vitestRunner` defaults `prepare` to the engine's installer. Still open: `worktreeRoot` defaults to a temp dir the sweep never reads. Fork: the factory adapts the declared runner with api-derived defaults (a runner declares what it lacks, the package fills it), or `runner` becomes a factory `(api) => Runner` in the schema and spec. The second is the cleaner contract; either way a consumer should never construct the installer or the base path by hand.
