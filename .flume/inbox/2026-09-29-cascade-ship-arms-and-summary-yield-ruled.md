# Ruled: cascade's not-shipped arms, and the completion summary's yield

- *Does cascade's build declare a `shipped` predicate* — neither (a) bare nor
  (b): the example's behavior stays, and the divergence is declared at the
  site — the handoff's two `not-shipped` arms are written for the author who
  copies it and declares `shipped`, so the hand-folded fixture is the lens on
  purpose (`engine-boundary.md`, *Opinion ships by name, opted into*;
  `engineering.md`, *The fix lands at the mechanism*, "a divergence that
  genuinely is the right depth is declared and cited at the site"). A
  declared site is never filed against (`posture-sweep.md`, *Routing*), so
  the dead-plumbing lens stops re-finding it. An artificial predicate would
  teach worse than none.
- *Does the completion summary name a run that shipped nothing* — (b), and it
  is the code short of the spec, not a spec change: `spec/loop.md`, *Exit
  codes — the run never lies to CI* totals the spend "so what a run cost is
  read where its outcome is", and the outcome is what shipped. The summary
  names the run's shipped tags unconditionally, with an explicit
  nothing-shipped spelling. Not (c): a clean-exit count is new surface for an
  unmeasured case.
