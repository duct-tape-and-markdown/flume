# Ruled: presence is state, location is kind, content is for the reader

Operator's ruling, from reading the harness against the engine. The engine
keeps every fact it acts on as a file whose presence is the fact and whose
path is the kind; the package grepped three of its own: a question's status
out of a heading, a park out of a commit's path list, a note's kind out of
its prose. `spec/harness.md` *Records as one file each* now states the
principle, and the two artifacts move: open questions become one file each
under the plan's `questions/`, present while open, deleted when answered, so
any session may add one; a parking note lives under `notes/parked/`, so the
kind is the path and the records gate holds it. `.flume/PROTOCOL.md` says
the same for this repo.

What derives: the questions directory and its drain (one file in, one file
out, the way records already work), the parked subdirectory with the gate
arm, and the removal of every `^##` and status-word read in the slices.
The single `open-questions.md` migrates once, one file per section.
