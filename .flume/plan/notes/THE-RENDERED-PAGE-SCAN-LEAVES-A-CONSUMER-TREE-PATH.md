# The same coincidence stands at two sites the rendered page arm does not reach

Shipped, on the page arm alone: `scanRenderedCitations` now takes a
`consumerRoot` and drops a `*.md` name under it before the disk read, the
repo scan handing it `DEFAULT_STATE_ROOT` off the verb that writes that
tree. `.flume/PROTOCOL.md` in `HARNESS_HELP` was the one live site; the
agreement pin against `protocolPath(DEFAULT_STATE_ROOT)` is now the only
thing that reds on a hand-spelled copy, and its comment says so.

Two sites left, both the same accident and neither decidable from this
entry:

1. The **section arm** of the same scan still resolves a cite against this
   tree. No shipped surface states one under a state root today, so there is
   nothing to judge — and `spec/harness.md`, *Adoption and upgrade* forbids a
   shipped page naming a section in a consumer-owned page, so the arm is the
   refusal that should catch one. It would not: this repo holds
   `.flume/PROTOCOL.md` with those headings, so such a cite passes green off
   our own copy rather than reding as the forbidden shape. A gate for the
   *rule* (no section cite under the consumer root, from a shipped surface)
   would be decidable; excusing it the way the page arm does would not.

2. `harness/layout.ts:163` states `` `.flume/PROTOCOL.md`, *Records: one file
   each* `` in a doc comment — a page name **and** a section cite into the
   consumer's tree, both answered today by this repo's own copy. A doc comment
   is not in the paragraph's list (PROTOCOL, a prompt, a `--help` literal),
   and a `.d.ts`-reachable one is hover text read in the consumer's repo where
   that file does exist, so whether it is the same defect is a spec question,
   not a mechanical one.

Fixture note: `FIXTURE_CONSUMER_ROOT` is `.probe`, and the `probe adopt
--help` surface carries both halves — an absent page under the root and one
outside it — so the exemption's prefix and its refusal are pinned together.
