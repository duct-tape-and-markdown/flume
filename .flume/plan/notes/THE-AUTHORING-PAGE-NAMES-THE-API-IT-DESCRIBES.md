# The api-member pin is one page; two consumer surfaces carry the same hole

Shipped: 14 members named, and the converse arm in `tests/chain.test.ts`
reading `buildFlumeApi`'s own keys against the authoring page's prose spans.

Two things the next derive may want.

1. The bar is the page's **prose** spans, not its bytes: a fenced sample is
   code the page is showing. Measured this tick, all 40 members clear that
   stricter bar, so nothing is carried by a sample alone. If a later member
   is named only inside a code block the pin reds, and the fix is a sentence,
   not a looser matcher.
2. `INTERFACE_PAGES` (`tests/helpers/pageAnchors.ts`) names three pages the
   page-to-surface arm judges — the authoring page, `docs/CLI.md`,
   `README.md`. Only the authoring page now has a converse. The README and
   the CLI page describe narrower interfaces (the verbs, the adoption set),
   so "every api member" is the wrong demand there; what may be right is the
   same converse over each one's own subject — every verb `docs/CLI.md`
   names, which `tests/cliHelp.test.ts` already reads off the shipped help.
   Worth a look before filing: that may already be covered.

No debt observed in the page itself. Four of the fourteen — the error
classes — had no home on the page at all before this tick; each now sits at
the refusal that raises it (chain load, render, queue parse, tip claim)
rather than in a list of its own, so nothing restates the api's shape beside
`src/flumeApi.ts`.
