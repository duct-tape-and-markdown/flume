# The two mode tables disagree on render-refused

Shipped: the park walls the entry at selection, told from a continuation by
`isContinuation` (`harness/standingRefusal.ts`), which both routing surfaces
now index.

Two things for the next plan tick.

**1. `render-refused` is the same field report one mode over.**
`PLAN_RESOLVES_STANDING` (`harness/standingRefusal.ts`) calls it plan's, and
says a walled render is unmovable by a retry — "forever, since nothing about
the tree changes between attempts". `RESOLVED_BY_A_PRODUCER`
(`harness/handoff.ts`) calls it retriable — "spans and hooks that resolve
against the environment". I shipped the spec's enumeration verbatim ("a clean
exit, a park, a merge the queue must answer"), so a render refusal still
re-dispatches every tick: no agent price, but a provision and a wave per tick
until a human rewrites the entry. Either the handoff table gains the mode or
the standingRefusal sentence is wrong — a decision, not a defect I could pick.

**2. An elided footprint now walls, not just routes.** A `not-shipped` whose
`touchedPaths` was cut past the writer's bound still reads as the park, which
was the safe direction when it only woke the drain and now also holds the
entry back from build. The record still states its own `omittedPaths`, so the
drain sees the elision — but the cost of that safe direction went up, and
nothing measures how often the bound is hit.
