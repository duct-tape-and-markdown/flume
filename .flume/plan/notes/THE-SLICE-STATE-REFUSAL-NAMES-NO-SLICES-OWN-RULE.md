# The slice-state headline's negative is stem-matched, not clause-matched

The headline's roster was a paraphrase, not a quote: the base said "coverage
dropped from a rotation still open" while the sweep rule writes "the open
rotation's covered set dropped N module(s)". So no containment check over the
rules' real clause text could have caught it, and a "headline is the same
whichever rule fired" check is green on the base too (one literal served
every slice). The case that reds is the headline against `JUDGED_SLICES` with
`plan-` stripped — "derived" carries "derive". That is the one mechanical
handle the defect left; any finer read of "a slice's wording" needs a
stopword list, which is a hand-listed vocabulary the next rule joins by hand.

Worth plan knowing: the same shape is open wherever a gate's headline
paraphrases what its details quote. `refuse()` takes the two halves from one
caller, so nothing structurally stops a second headline restating a clause it
already hands back. If that recurs, the fix is likelier at `refuse` — a
headline composed from the count and the gate's own subject — than at another
per-gate prose entry.

this entry's own pending JSON.
