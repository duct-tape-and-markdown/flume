# The walled row promises a re-cherry-pick no actor performs

A span abandoned when its wave walls is rowed `wave-walled` with `baseSha` and
`headSha` so that, in the row's own words, the span is re-cherry-pickable from
that row alone — and `headSha`'s doc says a passed span "must be
re-cherry-pickable from the verdict alone, never re-run at full agent price".
Nothing reads the row to re-pick it: the next start's teardown deletes the
branch and the entry re-runs its agent at full price. Narrated, not built
(`engineering.md`, *Narration is the ladder's bottom rung*; `posture-sweep.md`,
*Standing lenses*, dead plumbing).

A-MERGE-STAGE-THROW-STATES-WHETHER-IT-IS-ONE-SPANS-OR-THE-TRUNKS makes the
walls rarer — only a trunk-scoped throw will abandon siblings — but does not
answer what happens to the spans a trunk-scoped wall does abandon.

**The decision, because both arms are a real choice and one is subtraction.**

- **(a) Build the recovery.** A later merge stage re-picks abandoned spans from
  their rows: the saved cost is a whole agent span per abandoned entry; the
  price is a second carry path keyed on verdict rows, with the branch
  teardown's lifetime moving so the sha it names still exists.
- **(b) Delete the promise.** The rows keep their shas as facts for an
  operator's `git cherry-pick`, and the two doc claims stop asserting an actor.
  Subtraction first; the entry re-runs its agent, which is what happens today.

Plan's read: (b) is what the tree does, so (a) is a feature ask with an agent-
price argument behind it — the operator's call, not a defect fix. Either way
the claim and the code agree afterwards.
